# 12 掌握验收：能解释、能推演、能纠错

本章验收你的掌握程度，不代替软件测试报告。初始状态全部为**未执行**；阅读文档、抄参考答案和看到历史验证通过都不能自动打勾。

## 1. 通过规则

每项按三级记录：L1 能复述；L2 不看正文独立画图/推演，关键事实准确；L3 能处理随机变式、给出取舍和测试。建议全部达到 L2，A06、A08、A11、A14、A15 达到 L3，才能称为这套材料的面试准备验收通过。数字是学习安排，不是项目性能阈值。

以下错误出现时，对应项必须重新练习，不能用别项分数抵消：把模型等待放在长写事务里；声称取消回滚已完成外部效果；把旧向量完成当 current；把模型 replay 当真实环境验证；把咖啡馆方案或对方未公开架构当项目实绩；隐藏实验失败/分母。

## 3. 每项怎样提交，怎样判断答到了深处

矩阵用于导航；下面规定实际交付。口述可以配纸笔，不要求启动应用或调用付费模型。时间是练习建议，超过时间可以继续学习，但不能把查阅后的答案记成独立通过。

### A01：画图后必须跟一次代码

画出用户输入、Run、Item、事件、模型请求、工具、认知和界面的关系。然后从 `AgentRuntime` 找到一次运行开始与工具执行入口，从 `RunEventService` 找到“持久化后发布”的顺序。提交图和三个定位点，并用自己的话解释每条箭头传的是什么。

通过时应能回答：窗口显示的是事件投射，任务身份不是某次网络请求；工具结果会进入后续模型步骤；语音共享产品合同但有不同驱动。加题：同一个事件再次到达时，为什么不能再插入一遍？要区分同序号同内容的重放与同序号不同内容的冲突。

### A02：写出工具执行的四个时间窗口

任务为“读文件，按要求改名，再生成摘要”。在读取前、读取完成后、改名已提交但回执未到、摘要生成中分别插入“先别改名”。提交四行表，分别写输入版本、可取消动作、已经发生的效果和最终回复。

最低要求是四行不能同答“全部取消”。外部已接受的改名可能需要确认状态；只读结果可以保留为已发生事实；未执行的旧写入应停止。再说明按需计划如何调整，以及审批为什么不代表业务前置条件永远有效。

### A03：从事件入口讲到异步结果与最终行动

阅读依据是第 03 章。交付五份材料：入口图、触发表、三条并发时间线、四处中断恢复表、咖啡馆迁移说明。不能只交一张 Claim/Intent 变化表。

**第一步，讲清真实入口。** 从用户点击提交、窗口正文变化、像素变化通知、工具结束、持久化时间到期五种生产者开始。每条说明谁持有原始事实，调用哪个适配函数，何时入库，以及哪些字段来自宿主。尤其区分 user_engaged 控制与真实 user_message 原文，以及 visual-change 信号与真正图片。

**第二步，手填触发表。** 给出八类输入：纯按键数、带新文字的 interaction、重复前台画面、离开后返回同一文档、idle、分析前拉取的 frame、机会撤销、真实用户 utterance。分别回答是否缓冲/保存、是否安排考虑、是否取消在途分析。给出 t0 和 t0+0.6s 两个事件，按当前一秒窗口计算最早考虑时间，说明它不是不断后移的 debounce。

**第三步，推演三种在途变化。**

| 必答情形 | 时间线必须出现的内容 | 考官追加变化 |
| --- | --- | --- |
| A1 还在分析，切到 B 又返回 A | 新来源入库、#task 不重复、focusRevision 改变、提交与动作资格分开、A2 后续读取 | A1 只引用历史而不依赖前台 |
| A1 还在分析，用户说先别改 | 用户控制先入库、代际增加、abort、相关 Run 让路、迟到结果失效、普通回答走自己的 Run | Provider 不理取消，之后才返回；再问永不返回 |
| 检索等待期间新 utterance 同代际到达 | 原 receivedThroughSequence 不升级、完成阶段补材料、行动检查新用户接收、旧决定不执行 | 新话改成屏幕引语；或两条话 observedAt 相同 |

每一行都要说清当前是“分析模型”还是“已分配 Run 的执行模型”在等。考官可以把任一 await 前后位置交换，要求重新推演；只复述原案例不算通过。

**第四步，插入退出。** 分别停在 analyzing、awaiting_recall、ready 尚未绑定、dispatched 已绑定。说明是否已有状态提交、到期条件能否恢复、原 Attempt/Run 怎么处理、是否会再次生成消息。再插一例“旧请求失败前新消息已到”，解释恢复计数与用户控制代际为何不是同一个东西。

**第五步，迁移到 NPC。** A 进店、看钟、与 B 交谈、直接叫店员、订单完成、生成期间离店。写每步的可知事实、推断、目标与可接受行为；新增另一个 NPC 同时想插话。必须指出世界版本、玩家/会话路由、发言权和实际播出回执是游戏侧新增合同，当前桌面单实例不能直接当多人架构。

评分按五份材料各 0–2 分：0 分是只有术语或流程错误，1 分能讲正常路径但经不起变式，2 分能解释具体 owner、身份、等待边界和失败后续。至少 8/10，且以下关键错误必须全部消除：把每次唤醒当新模型请求；把 abort 当强制结束；把状态提交当行动许可；把所有版本都叫 userGeneration；把 Run completed 当用户已听到；把补读进度当作所有积压已处理。该分数是学习验收要求，不是模型性能指标。

**追加必答：普通 Chat 与多人规模。** 用第 03 章第 27–29 节的案例提交下表；各行均须独立完成并通过追问，不能用原五项总分抵消。

| 交付 | 必须讲清 | 现场变式 |
| --- | --- | --- |
| 三个事项、两个 Chat 的归属图 | 当前注意只是指针；普通 prepareTurn 读已提交背景，不先分析当前问题；一次主动行动最终绑定一个 Chat | 当前注意论文，另一个 Chat 问旅行：现有代码会读什么，哪里有改进空间？ |

出现以下任一判断仍需复练：每次分析必有下一次固定时间；打开 B 站必然疲劳；每个应用必有独立 Situation；外部 ChatGPT 网页里的问题就是对 CharaMate 的指令；重要度排序能解决无限积压；世界 tick 改变就废弃所有模型结果。联合检查见 A08、A09、A13，当前均未执行。

个人结果仍为**未执行**。记录实际口述/图表、被追问卡住的位置与复练结果后，才可标记掌握。

### A04：从一句原话重建字段、数据库行和完整生命周期

使用第 04 章的林岚案例，第一次可以边读边完成；正式验收换朋友名字、咖啡类型或输入顺序，闭卷重建。提交七份材料：调用图、结构化提议、字段归属表、数据库核账表、事务与索引时序、修订图、故障恢复表。

| 评分项 | 必须独立说明的内容 | 核对方式 |
| --- | --- | --- |
| 入口与来源 | 谁调用空参数 memory.record；当前／前一 Run 的消息范围；主要来源与说话人的区别；原文如何入队 | 在图中标 Run、Message、Item、episode 和 work 各自身份 |
| 提议与字段 | 两人分开；实体 key 如何变 ID；原输入／模型／宿主／派生值；未知时间和初始 confidence 的含义 | 随机点名十个字段，至少覆盖四类来源，逐项说明生成者与落点 |
| 原文与证据 | quote 是原文子串；窗口内偏移怎样还原；同一 U1 支持两条记录 | 手算两个引文区间，再在前面加入 emoji 重新计算 |
| 写库与索引 | 两条正文与语义；共享来源；实体角色；FTS 同步；编码工作异步；表约束与字段索引区别 | 解释第 04 章核账表的每个数量，不能只背数字 |
| 更新与恢复 | create／revise／support；三类历史处置；片段事务与完成回执；版本冲突与迟到索引 | 处理下面随机抽取的故障卡，画出最后的当前版本与任务状态 |

每项按本章 L1／L2／L3 规则记录；五项均独立达到 L2 才算 A04 通过。关键错误不能用别项抵消：让回答模型自编原文；把人物归属写反；声称模型生成全部 ID 和索引；把 confidence=1 当正确概率；认为所有 metadata 都进入向量；把来源入队当保存完成；把全 episode 当一个不可分事务；让迟到向量改变当前事实。

至少抽三张卡，其中一张必须是提交或等待期间的变化：

- 两条提议中的第二条引用了不存在的原句：哪些事实回滚，哪些来源和工作保留？
- 当前比较为 V1，用户在等待期间提交 V2：何时发现，为什么旧提议不能直接覆盖？
- 同一 U1 通过 Cognition 又来一次：哪些身份相同，为什么不能算新独立经历？
- 第一片段已提交，第二片段失败：游标、事实和重试分别怎样变化？
- 编码器无法启动，形成回执已经成功：能说什么，哪些检索能力尚不完整？
- 先完成 V2 编码，后返回 V1 编码：能否保存，为什么不能恢复旧事实？
- 旧版已被纠正，又被某个摘要引用：摘要能否作为当前证据？
- 两人同名且别名均命中：哪些是程序保证，哪些仍需判断或澄清？

修订图另保留三个变式：真实偏好变化、明确纠错、管理页直接编辑。必须分别解释 retained_history、corrected、unresolved，并画一个依赖旧版的摘要。个人状态仍为**未执行**；检查文档与示例不代替你的口述和独立推演。

### A05：亲手完成一次检索和索引推演

新增必答依据为 [第 15 章](15-context-activity-retrieval-walkthrough.md) 第 3–7 节和末尾七项变式。解释 FTS5/MATCH/BM25 的职责、跨通道轮转、Main 与 Worker 的分工，并画出当前查询排除 R1/R2、R3 尚未编码和选择期间 R4 提交的三种结果；不得用“新版本优先”概括全部规则。

先接过 A04 已形成的两条偏好，明确它们的主体、当前修订、全文索引和向量状态，再完成本章后面的索引练习与多问题检索练习。提交从原始文本、修订、词法索引、向量任务、候选、选择到最终供给的表。每个阶段至少指出一种独立失败，尤其区分正文遗漏条件、索引未完成和证据已供给却被回答模型用错。

不能只写“建向量库然后查 topK”。应解释切分以模型 token 为约束、查询与文档编码规则可能不同、模型键变化不能混用旧向量、结构过滤先限定合法范围。最后说清何处能补检索，何处必须承认证据缺口。

### A06：完整纠错链

按下一节连续解释，随机抽两张竞态卡，不能预先挑容易的。必须给出同步更新、异步等待、短事务、复查和可见结果的顺序。每说“检查版本”，都要指出检查哪个对象、期望值从哪来、失败后做什么。

这是跨章总验收。若只能讲 Memory 表更新，却讲不清当前输入如何阻断旧行动，或把最终证据重读当成整个流式回答的永久保证，尚未通过。

### A07：恢复表要覆盖崩溃两侧

至少画认知交接、记忆形成、外部工具三个边界。对每个边界分别写提交前崩溃、提交后尚未通知崩溃、通知重复的恢复结果。说明事实记录、进度和通知谁拥有。

本地交接应出现“入队和确认同事务、提交后唤醒”；外部动作应出现“稳定身份、效果查询或去重、无法确认时保留未知”。不能把网络调用塞进本地事务后宣布不存在重复效果。

### A08：白板必须包含可执行的提交点

在 30 分钟练习中完成职责图、可见事件、有限动作类型、状态转换和完整轨迹。至少明确订单、发言权、记忆和剧情状态的负责方。随后画两个 NPC 同时申请发言时谁能原子地接受一个。

通过时应能描述提交后的发送与曝光回执，说明发言被接受不等于玩家听完。加题：玩家离开后又回来，为什么旧邀请不能只靠 `present=true` 恢复？需要区分此次在场与旧机会。

追加 [第 16 章](16-npc-persona-hints-and-evaluation.md) 的开放对话、卡关与补丁变式：说明未设定身世如何回答；玩家拒绝发生在提示入队和播放之间怎么办；同一 Boss 两个版本混存时如何查询与展示。交付提示分支与版本依赖表，必须区分规则资格与模型语义判断。

### A09：给成本和性能各算一次账

## 4. A06 综合验收：一口气讲完整纠错链

考官读题：“用户把周五约定改到周六。旧认知分析还没返回，旧记忆索引仍在计算，NPC 正准备主动提醒。请从新输入开始讲到最终回答。”建议给 6–8 分钟，不要求逐字背诵。

必须出现这些因果连接：

1. 当前真实用户输入/控制有接收顺序，Run 输入 revision 更新；新消息不等待全部记忆形成。
2. 旧分析尽力 abort，提交仍检查本轮已读实体版本与控制代际；新用户接收边界还要在行动阶段检查，取消通知不是唯一保证。
3. 同 generation 的晚接收真实 utterance 也可能使旧行动失效；引用旧话不能冒充新控制。
4. 同步 `memory.record` 与后台 handoff 是不同接入路径；自然回应不提前谎报落盘成功。
5. handoff enqueue 与 ack 同事务，commit 后 wake；崩溃不会让已确认交接的 episode 消失。
6. Formation 在事务外等模型，校验批次；事务内重查 current revision，写 revision/处置/pointer/进度；冲突重读。
7. 时变、真正纠错与手动编辑分别处理旧内容；不能一概物理删除或都标 corrected。
8. 向量绑定精确 revision、内容 hash、模型与维度；历史索引可合法完成，事实资格另查。
9. 新索引未完成时，当前输入/可用读取路径与 incomplete 信息如何使用；立即新 Chat 不能靠空缺口字段宣称知识齐全。
10. Recall 选择后还要经过预算和精确版本回读；不偷换证据选择过程没有读过的新版，并更新 coverage。
11. 自主行动 dispatch、allocation.bind、publish 前查选中依据；无关变化不应误取消，当前依据变化应取消。
12. 普通流式回答与自主表面投射的保证不同；已显示/已播/已执行内容不能回滚现实，只能停止后续并更正。

及格不是说出十二个词，而是能解释为何有这个顺序。例如“为什么先存后 wake”必须讲到崩溃窗口；“为什么重读同版”必须讲到选择理由与正文不能脱钩。

```ts
async function rememberAndReply(source) {
```

| --- | --- |
