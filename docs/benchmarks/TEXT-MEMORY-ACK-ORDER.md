## 选择与后续边界

保留A0的原因是A1没有触发所研究的提前回应机制，且出现一次无新增记忆的前台等待。几次较短的同步写入不足以证明提示收益。当前Main保持原指令，A1仅存在仓外；不添加设置、运行时开关、第二形成路径或候选依赖。

等待问题继续推进。更明确的表达顺序与调整前后台职责是两种不同假设，不能同时修改后把收益都归给提示。当前后台链路由Cognition分析提交有依据的claim变化或关闭Episode后产生handoff，再由既有桥接器同事务保存Memory工作和确认handoff；不是Run结束就无条件形成所有信息。新Chat也不会等待该链全部完成。Memory检索的形成缺口仅覆盖已移交工作，不能据缺口为空断言所有原话都已形成。
