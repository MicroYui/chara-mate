# MEMORY-ADAPTIVE-CONSOLIDATION：有来源的局部巩固与同来源批次共享检索

日期：2026-09-16。集成状态更新：Coverage/G 所选实现已从隔离共同 v13 合入当前 Main v21；其原七文件组合结果保留在下文，最终同版产品验收仍未完成。本文件只记录巩固选型，不能据此宣布整个记忆系统成熟。

## 选择及产品行为

选择一个本地后台巩固实现：对已形成的真实记忆，在同一个 Recall 中查找相关经历、条件和变化，生成带原始来源依赖的有限理解；同一实际形成批次的多个问题共享一次检索。人物、条件、真实历史、纠错和用户明确表达的感受必须保留。理解以 `inference` 保存，不能代替原始事实，也不能把角色承诺写成已经完成的行动。

本次包含两个有先后关系、分别测量的决定：

1. **覆盖语义修复**：库中还有经历未形成，不等于本次已经供给的准确引文不可用于局部总结。须分别表示全库未知、本次检索覆盖、实际供给的来源区间、与未完成形成工作的已知连接。
2. **批次共享检索**：同一实际 Formation 回执产生的当前事实，可在同 owner/persona 内共用一份多问题 Recall。它们仍各有问题、证据、总结决策、事务和回执，不强行合并成一个语义主题。

覆盖比较证明了旧范围解释会错误阻止合法的局部巩固；它没有证明单独增加摘要节省成本。随后 G 比较证明，采用修复后的同一语义时，批次共享检索降低了本组实际总调用和 Token，且未观察到新增事实错误。两项证据不能互相替代，也不能把摘要数量称为物理压缩或长期体验收益。

## 2026-09-17 原连续场景暴露的独立支持计数修复

此项是原固定48场景中发现的正确性修复，已随最终Memory组合合入Main，原材料一次真实复测仍待执行。原 `f09-bounded-waiting` 四个普通回答点通过，但后台 `model 000:00056` 的有限模式提案被宿主拒绝，原因是 `One context or day cannot establish a cross-context pattern`。失败的实际五项原件和五组准确引文完整供给；其中用户原文分别来自 3 月 2 日的冰箱采购、3 月 16 日的工作评审、3 月 23 日的演出分享，另有两条助手承诺。原失败、29.205 秒生成与全部费用保留在冻结评阅 `24db5e23392032b951a72c597d071ad283c8b5ddf708b10e3cfa06f259fed8bf`，不因后续解释回写原结果。

宿主当时不是直接判断真实语义情境，而是对每个原始来源按 `recordedAt, work.id` 选一个处理记录，再数其中可选的 `situationId`。普通记忆入口没有 PFC 标签，后续 PFC 入口可能有；同一原文的 `recordedAt` 相同，最终由工作 ID 的字典序决定是否计入标签。实际 3 月 2 日取到有标签的一项，3 月 16 日即使已有 PFC 标签仍取到无标签的一项；3 月 23 日在失败发生时标签尚未形成。真实工作 ID 是依照捕获的 intake ID/version 与当前公式复算，未直接读取原 work 表，不能将复算字段说成原持久快照。

2026-09-17 重新阅读 [SQLite Window Functions](https://www.sqlite.org/windowfunctions.html)：`ROW_NUMBER` 按分区与排序分配序号是官方查询语义；按本项目工作 ID 选哪个可选标签是当前代码行为；“至少两个 UTC 日期、两个 PFC 标签才允许有限模式”是 CharaMate 旧启发式，既不是协议限制，也不是独立经历的证明。本次原现场足以否定这种标签硬门槛，不需要新增研究题目。

选定修复以实际引用的原始用户来源作最小结构检查：去重 canonical `raw_speaker=user` 且作为原形成 primary 的 source；多条 Revision 引用同源、后台再处理、助手复述不增加来源数。有限模式至少需要两个这样的实际被引用来源，但源数本身也不证明语义独立性。日期与已记录的 PFC 标签只说明材料覆盖，不作硬否决；缺标签不等于相同情境，同一天可以有不同经历，跨午夜也不能自动变为跨日稳定。模型继续阅读完整原文、时间、条件和反例，判断是否存在真正重复的独立经历，或应保留情节总结/原件。后来的珍视本身不能自动充当原事实的新独立支持，结构计数不能代替这项语义判断。

2026-09-18（UTC09-17）收口：准备阶段只统计本次提供非空准确span的canonical用户primary来源，输出后用已验证的实际citation来源再计数。逐Revision候选来源可能重叠，不能相加当作独立经历；未引用、仅context和助手来源不凑支持。至少两个实际用户原始来源只是必要结构条件，模型仍须判断经历是否独立及其适用范围。旧按work散列挑标签及两个UTC日期/标签硬否决已移除。

## 问题来自实际连续运行

此前 L 使用六周连续材料、真实 Formation、SQLite 和冷 Chat。72 个唯一来源中 67 个成功形成、5 个失败；六个重放不增加独立来源。周 2/4/6 共支付 439 次巩固相关模型调用，原逐项 FIFO 路径未证明稳定的查询收益，不能作为最终默认。

周 4 的 82 项工作全部保留原事实，其中 63 次实际调用总结模型、19 项在检索后只剩一条事实而直接保留。部分总结因“全局部分经历尚未形成”放弃本次已有充分来源的材料；63 次中 61 次所供来源与该失败 work 的已知 primary/context 来源没有交集。无交集只证明没有这种可观察连接，不证明语义绝对无关。另有 82 次 Recall、86 次 Selector，说明逐事实付费检索的成本真实存在。

实际 w4/w6 已完成总结材料的完整重复数为零，因此未新增跨轮缓存。廉价候选数也不能区分值得综合的跨情境模式；未用共同实体、同一用户、同一天或 graph 有无边作为硬性语义门槛。

## 选中实现的完整路径

已有来源入库和 Formation 负责原事实；当前事实或支持来源变化通过既有 `memory_work(kind=reconcile)` 记录巩固工作。工作身份包含实际材料版本，既有游标固定本轮有限的待处理范围，新到事件进入下一轮，不在模型等待期间保留 SQL iterator。

`pendingGroups()` 只依据最近实际已完成 Formation 回执中仍为当前 Revision 的变更列表分组，并再次限定相同 owner/persona。手工记录或没有对应批次的工作仍作为单项进入相同执行器。分组只共享检索传输和一次实际结果，不声称同批次事实相互支持。已有材料预算放不下组合问题时拆成更多请求，不引入新的批次数量阈值。

每个成员从共享 EvidencePack 中取得属于自己问题的证据。覆盖材料明确四个层次：

- `namespaceFormationIncomplete`：命名空间仍有未形成经历，只表明未知范围。
- `retrieval`：本次每个问题的覆盖、缺口、预算裁剪及检索未穷尽说明。
- `supplied`：实际存储与本次真正供给的 exact Revision/Source/span 对照；来源 ID 数量相同不等于片段全部供给，更不保证正文每个分句均得到支持。
- `knownFormationConnections`：实际供给来源与未完成 work 的 primary/context 连接。未读失败原文不能当成已看过，无连接也不能宣布没有相关未知经历。

相关检索仍使用既有局部工作集；最终巩固的metadata、必要原件与精确引用按完整请求分配，见[完整巩固材料](MEMORY-CONSOLIDATION-CONTEXT.md)，不再沿用16,384作为最终必要材料额度。更新已有理解时必须看见并保留所有仍有效的旧依赖；必要来源不足、条件不清或预算不够时保留原事实，不截断必要条件来换取摘要。只剩一个原始证据时不另付总结调用。跨情境模式要求核对真实独立经历；`distinctUserDays` 是 UTC 日期桶，不能把跨 UTC 午夜的短会话或两次认可当成两天稳定偏好。

模型在事务外产生有来源的 `episode_summary` 或 `bounded_pattern`，host 校验每个依赖、准确引用和主体范围。提交事务重验父版本、历史资格、原始区间和派生目标版本；任一变化则拒绝本次写入。派生内容通过既有 Memory、来源片段与 `derived_from` 关系保存，再由同一索引和 Recall 消费。原事实继续存在；删除必要来源或纠正父事实必须使旧派生内容失去依据，合法原文回收但准确引文仍在时不误失效。

每项已完成结果立即发布，后续成员取消不能抹掉已提交内容。取消把当前工作还原为 pending，崩溃后 running 工作由既有启动恢复回 pending。普通巩固错误保留为 failed，原事实仍可检索。当前 Main v21 已采用[巩固恢复 Decision](MEMORY-CONSOLIDATION-RECOVERY.md)：启动或正常 drain 在真实处理器版本就绪时恢复仍对应当前来源版本的旧版 failed；普通文字 Run 首个真实完成模型响应经同一个 MemoryProviderRecovery 对象，同时通知 Formation 和 reconcile。巩固的同版恢复仅接受已经失败且实际请求 profile/api/model 匹配的 TIMEOUT、UNREACHABLE、RATE_LIMITED，不借其他模型成功恢复，也不为尚在执行或未来的失败保存重试额度。Main 的配置变更 listener 继续调用 memoryMaintenance.retry()，并取消在途巩固以重新绑定配置；同版语义/来源错误不会因普通对话成功而循环重试。

共同版本的 Main 已实际构造 `ModelMemoryConsolidation`，每次读取当前默认 Chat profile，创建 runtime 前后检查取消信号。App 的 `MemoryForegroundActivity` 从已提交 Run 状态和实际 Voice snapshot 投影当前执行集合：任一 Run 正在运行或 Voice 仍活跃时暂停巩固；所有执行均空闲才继续。等待文字输入或审批可释放对应 Run 份额，活跃 Voice 仍独立持有。该集合不是第二份持久 Run 状态，也不增加用户内部算法设置。

## 覆盖语义比较：范围纠正，有实际消费但无整体节费

四个锚点来自原 L 真实 w4 闭库：封面转卡片、文字与音乐的条件性规律、纸城缺失引文、报告来源与失败 work 的真实连接。四类属于同一开发用户，不能算四个独立用户或最终 holdout。

旧描述 V0 与精确描述 V1 共用每锚点一次新的实际 Recall/Selector，之后各自调用新的巩固模型；这四次检索费用只计一次，没有复用旧总结。三对去除新覆盖字段后材料逐字相同；纸城一对因新增 metadata 占预算，证据从 8 条变为 7 条，移除未供准确引文的 revision `572fa0ce-319d-4268-a902-141d7d69292d`。该对保留在分母，但不能解释为纯措辞效应。

### 最终取舍、修复与单一路径

这是明确的事后产品取舍：承认 M 的实际漏答，仍选择修复已定位的查询合同后保留更简单的准备所有权，不为一次由前台搜索差异体现的完整性新增三个目录模块、跨域查询和额外模型排序。D0 具有实际完整性优势但本组代价较高，且自身也暴露过过滤掉角色记忆的路径；D1/D2 对 D0 没有新增回答完整性，交流日期也没有独立收益。此结果不能证明目录或预测在其它用户/规模无用，亦不以一个统计门槛替代整体判断。
