# MEMORY-COLD-INFORMATION-DEPENDENCY：普通对话何时需要回忆

日期：2026-09-16。集成状态更新：信息依赖契约已作为普通 Agent 指令的单一路径进入 Main v21；以下开发比较和代价保留，最终同版完整形成与普通冷消费验收仍待完成。owner：root。

## 问题与单一变量

已有检索器能够找到一些重要记录，但普通 Agent 在新 Chat 中未必会发起正确的问题。实际基线中，“下周怎么安排”“你接下来想做什么”会得到全新泛化建议，已形成的用户打算或角色自己的未完活动没有进入检索。这是消费入口的问题，不能只扩大候选数量或把所有旧记忆预塞进首个上下文。

两臂使用同一份通过实际形成流程生成的 SQLite 副本、同一 `gpt-6-astra`、同一实际 Qwen3-Embedding-4B 量化编码器、词法/向量检索、选择器与 Evidence Pack。普通 Agent 在新 Chat 开始，Cognition 上下文为空，不额外提供答案、Memory ID 或检索类别。唯一变化是 `agentInstructions.ts` 中的信息依赖契约：

- 做个性化建议、继续共同活动、解释共享线索前，先判断已知打算、限制、偏好、纠正或意义是否会改变当前选择。
- 这些信息尚未在有效上下文里时，用具体问题调用现有 `memory.search`；新 Chat 不代表此前关系和经历不存在。
- 问候、自包含的一般问题不强制检索；当前明确意愿优先于旧偏好。读取不等于必须把旧事复述出来。

不增加每轮预分类调用、单独 Planner、关键词路由、第二套检索通道、产品开关或强制 topK。本次比较不能支持另造一个信息需求服务；候选首先使用已有 Agent 推理与成熟检索契约。

## 开发比较与实际代价

20 个相同问题分别进入两臂：7 个适用的历史依赖问题、1 个可选个性化问题、1 个对应人物没有历史资料的问题、11 个一般问题。形成记录来自更早的 12 个完整故事；本轮消费比较不重新生成两套不同 Memory。这里的冷状态是明确隔离消费入口的开发设计，最终独立验收还要经过正常情境收束，不能人工清空状态制造冷启动成功。

| ------------------------ | --------------- | ---------------- |
| Run 完成 / 等待输入      | 19 / 1          | 18 / 2           |
| 有 usage 的模型请求      | 32              | 45               |

| Run 墙钟中位 / p95       | 7.43 / 43.39 秒 | 12.06 / 28.44 秒 |

观察到四种具体遗漏得到改善：安排时间时读到更新后的 7 月 14 日约定；安排下周时接续此前论文打算；回答自己的计划时接续角色自己的叶片册子；讨论读书会时保留场地、非排名形式与不解释家庭情况的限制。原本已经能正确处理的少见共享线索，两臂都保持克制，没有为了展示记忆而讲出伤心背景。

收益伴随成本：候选多 13 次模型请求，输入增加 72055 Token，输出增加 2131 Token，检索多 5 次，中位墙钟更长。它还在已知兄弟过敏、另一位新人物饮食条件未知的场景，多要求用户回答一次结构化问题；基线已能给出有用且不混淆人物的建议。这项额外管理负担计为候选代价，不能把所有 `needs_input` 都计成高质量谨慎。p95 数值受小样本与 Provider 波动影响，不能作为性能改善结论。

四个具体遗漏是逐例对照结果，不被包装为总体成功率或显著性。一般问题只检查是否发生不必要的 Memory 检索，并未评判所有常识答案质量。当前复核由开发者直接读原话、形成数据库、关键 Pack、最终回答和问题卡片完成；不是盲化独立验收。

## 保留的输入与标注修订

首次形成开发运行存在一个 runner 的工具/执行模式配置错误，修正后对受影响原故事建立新数据库重跑，旧失败保留。不能把 runner 配置失败归为产品形成失败，也不能覆盖原结果。

消费评分又发现三处源资料与预设不一致：周末原话并未形成必须提及康复的计划；新出现的小周不是已知同事林川；朋友通话的问题没有对应朋友记忆，已有资料说的是同事工作会议。修订标签时保留原标注与原因，不让消费者看到标签，也不把正确“没有该人物资料”记作召回失败。两次修订记录 SHA-256 分别为 `c63a6c32f66c1a6574a54907f4b9798a9b7e272259370db9bfb492bbfbe1447f`、`1c88a1e807d428518dfd2aed4cdf428d28e5ff377dc4e735c538e9b1486e9278`。

## 暂定取舍与独立退出条件

暂选这个小的消费契约变化，因为它修复了普通入口的四种已观察遗漏，且没有使 11 个一般问题强制检索。不会因此增加独立 Planner 或扩大检索预算。合入仍取决于新的完整形成→情境收束→重启/新 Chat→普通消费路径，且要同时核对额外追问、是否真正需要检索和已取消意图不复活。

已预先冻结 8 个新故事、22 个检查点：日期改期对行程的隐含限制、暂时休息与未完计划、跨月少见共享含义、活动风格及家庭边界、同名亲属/同事、已取消旅行与引用文本、当前明确意愿、归属未知的屏幕小说。输入 SHA-256 为 `200ab1da6f0b0af821c48942de94adc0299c3d964b6d61c9bf06e7158f3a24da`；独立标签为 `8bf2bca95e9de1b03cbe1da486a654425a4eb57afd5fa80ba83651b75a1b0574`。运行器只读输入；是否为冷状态依真实首请求内容判定，温上下文单列。尚未执行，不把冻结计划当作通过结果。

最终仅保留被独立验收支持的一个 Agent 指令契约，以及由生产路径拥有的必要回归；候选副本、实验 runner、比较开关与原始输出均不进入产品仓库。最终结果出来后本记录更新取舍，不以此阶段宣布成熟验收完成。
