# 历史处置引用已验证原文中的精确片段

2026-09-16。状态：历史处置引用子区间修复已进入 Main v21；原相关验证结果保留，最终同版产品验收待完成。对应 Product §6.3.1，集成 owner：root。

## 实际问题和依据

真实 W32 自主生活轨迹中，用户说：“我现在出去跑点事。你可以继续自己的兴趣了，不用等我回来，也不用专门发消息汇报。”模型的普通引用选中这条完整原话，历史处置引用选中其后半句。两个引用都来自同一个当前主来源，但原宿主额外要求两段文字等长相等，因而拒绝了有效处置。

本日核对 `FORMATION-PROVIDER-RECOVERY-FREEZE.json` 对应的实际 FormationService：普通引用已有原始 UTF-16 区间和分段起点，并已逐字核实。等长要求是 CharaMate 原实现行为，不是来源资格或模型协议的必要约束。修复复用原有范围证明，不增加模型调用、持久状态或另一套来源解析。

## 选中的实现

处置引用只可使用本形成单元中已经验证的同来源 primary citation。宿主在这些实际引用内寻找精确子串，映射回原文 UTF-16 区间，再核对原始分段。只有一个唯一原文区间匹配才接受；多条引用若指向同一区间只算一次，两个不同位置均能匹配则仍拒绝。

不能借用另一形成单元、上下文来源、相同文字的其他来源或普通引用之外的片段。`corrected` 和 `all_prior` 仍要求真正的当前主用户陈述，目标版本、历史范围及事务提交规则不变。处理器版本升为 `source-evidence-formation-v17-historical-citation-subspan`，旧版本失败可经过既有版本恢复机制重新尝试；在途 R1 语义修正实验的冻结源没有改变。
