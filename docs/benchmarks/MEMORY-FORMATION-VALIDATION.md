## 选择与实际问题

原跨周形成中，一条不合格的 support 会让整个片段无法提交。这个真实案例把用户当前提醒，当成角色重新作出承诺的直接观察；真正的旧 Voice 承诺此次只是上下文，不能获得新的主材资格。简单重新请求可能重复同一错误，按单位部分写入又会漏掉合法伴随内容并误推进完成位置。

选中实现先只读校验完整提案，收集明确的单位索引、字段和错误。仅发生这些领域语义错误时，同一个形成模型收到原完整提案、原材料和实际诊断，重新提交一次完整提案。修正不增加可用目标、不改变主材/上下文资格，不把用户转述改造成角色真实经历。整个新提案通过后，在既有事务内重验工作所有权、当前 Revision、保留引文，再一并提交。

正常路径零额外调用；失败修正最多一次是当前有证据支持的成本取舍，非 Provider 硬限制。网络、取消、未知存储和实际凭据错误沿原处理路径，不进入语义重提案。再次失败保留原已提交前缀和未完成位置。没有新增表、定时重试、永久错误历史或另一条形成流程。
