# MEMORY-RANK-FUSION：按问题与通道交替供给候选

状态更新：交替融合已简化为唯一实现并进入 Main v21；原旧缓存主比较和真实形成库的追加额度比较见下文，保留各自原版本、回放方式与测量边界。本记录只选择融合函数，不选择 Memory 总体架构、候选预算倍率或关系深度；最终同版独立质量仍待验收。

## 选择与理由

选用按原列表顺序、逐排名交替取候选的唯一实现，去掉 RRF 分数累加与 k=60。每个问题仍依次查询 lexical、semantic，最后保留现有 structured 通道；同一 Revision 只进入候选一次。显式引用优先、每问题每通道第一条保底、资格过滤、预算装载、一次关系扩展和最终重新检查均不变。通道顺序属于所选确定性读取顺序，不新增权重、模型或产品设置。

真实主比较两臂核心必要材料相同；自然小额度诊断中，交替融合让只有语义通道高排名的材料实际进入同一个 Selector 和最终 Pack。结合去掉 RRF 常数、分数表和最终排序的复杂性收益，选择交替融合。不是统计上总体优胜、SOTA 或商业整体准确率结论；没有把目标材料覆盖改善改写为五次实际回答胜利。

## 逐内容判断与反例

全部 28 题逐条记录于仓外 `QUALITY-REVIEW.md` 与 `QUALITY-ADJUDICATION.json`。评分人知道 Arm，不称独立盲评；Root 另独立阅读压力条件的原 query、候选、selection、Pack。全部 89 个最终 Evidence 实例正文逐字等于冻结来源，owner/basis 相对模型实际输入未变，source ID 均属于实际输入。

1. 两臂共同没取到的原摄影标签，不等于问答错误：问题仅问用户喜欢何种放松活动，未限定摄影；两臂选出的“喜欢船、海上放松”也是此库真实自述。原 gold 缺失仍为 0/1，不改标签；表面问题证据多解单独标出。
2. 四对辅助材料不同。RRF 在表妹摄影、搬家、游泳题多取真实归属或转变背景；交替在支付工作题多取稍后手冲咖啡，它不支撑支付的正向归组，但也可能作任务区分背景。不能把所有非 gold 材料自动算噪声，或因交替少两项就宣称语义更好。另一咖啡题的文档 ID 虽含 `irrelevant`，正文实际支持“不是单位采购”，按内容保留。
3. 小额度旧约定材料：当天原话 dense 第 3、无 FTS 匹配，RRF 全 rank 第 31、交替第 5；搬城原话 dense 第 4、无 FTS 匹配，分别第 45/8。这解释了 RRF 双通道弱匹配分数累加压过单通道直接材料的机制，不证明所有场景都如此，也不说明需要微调 encoder。
4. 忌日 1800 条件中，交替选到旧约定、今日请求、普通习惯；最终 fit 丢普通习惯，host 把 coverage 机械降 partial，而保留两条已覆盖原必要槽并支持当天陪伴。RRF 只有旧约定，仍足以解释表面“为什么日常工作复盘让位”；不能仅因缺今日句就判 supported 过度声称。4500 同理分别保留旧约定+习惯与三条完整背景。
5. 搬家两档诊断中，RRF 的南堤路实际搬家、海棠路取消等也都在同一 fixture user 域，不能按评测 groupId 当成不同真实人物。query 没有绝对时间、故事或实体限定，所以保留目标苏州/杭州材料 missing，却不把其它地址称主体错配、完全无关或错误答案。交替的目标材料更完整，五个诊断不等于五次最终回答胜利。
6. 游泳低额度条件中，RRF 保留春季攀岩与手腕不适后改游泳的真实背景；交替另取实际泳池频次与换气安静体验，提供更直接的目标内容。RRF 并非完全答错或无关。

Selector 只返回 ID 与覆盖声明；Pack 正文由 host 重读真实 Memory。本轮没有实际 Agent 自然语言回答、行为或陪伴结果，不把材料可达、合法 JSON 或进程 exit 0 当作最终体验成功。手工角色经历 fixture 的 basis 仍为 explicit_user_statement，即使 owner=character 正确，也不证明真实自主经历形成链正确。
