# 普通对话的已提交情境与续接刷新

日期：2026-09-17。状态：**focused-verified；18文件已集成，688项受影响检查与类型检查通过，最终语义比较未执行**。Root 拥有 Runtime、调用合同和 Main 集成。对应 Product §6 的本轮上下文装配。原正式吞吐冻结与结果不变。

## 已观察到的三种不同情况

原 v21 第六条件 two-projects/catalogue 的普通 m2 请求获分配 192267 Token 的补充情境空间，实际输入却只有 Situation rev7 的标题，summary 为空、claims 和 unresolved 为空数组。约30毫秒之前的 PFC 读取已包含同 rev7 的摘要和七条既存断言。因此，不能将这些空值解释为数据库中没有内容，也不能将此次失败归因于旧的 8k 行动额度。

该情境的新字体错误断言在后来的 PFC 输出才提交。m2 之前虽有一次 PFC 请求读到了完整错误原文，但该请求因新的用户控制取消，没有产生完成输出。已经读到来源、已经形成断言和普通回答实际采用是三个不同阶段；修复供给链不能替代尚未发生的分析。

m3 明确续接同一个 needs_input Run。其请求发生在错误断言已提交并被实际读到之后，仍带 m2 的旧 rev7 投影；没有新 prepareTurn。m3 当时表达冲水暂歇和不改文件，不要求角色强行排错，但已存在的信息没有刷新到下一请求是明确的供给缺口。

证据为仓外 `THROUGHPUT-V21-TWO-PROJECTS-PAIRED.md` 与原 prepared、message-entry、PFC、model 和 HTTP 记录。暂未记录当次普通读取的完整 allocation，不能声称知道究竟是哪一份原文耗尽其字节空间，也不能用不同预算的 PFC 快照替代该缺失记录。

## 修复前源码与修复要求

原 v21 的 `CognitionService.prepareTurn` 经 Repository.getSnapshot 使用通用事件读取页；该页默认本地快照及 coverage 的 JSON 字节额度为32768。它与行动读取按所选原始值计费的16MiB不是同一计量口径。Reader 先为当前状态保留局部视图，再读取原文及连续事件，最后才用余量扩展实体。getSnapshot 只返回 snapshot，丢掉 coverage 中的 allocation、未加载字段、摘录说明与真实 receivedThroughSequence。普通 Projection 因此只看到空值，并可能把未加载的关联状态标为 missing。

Reader 还将 snapshot.attention.lastReceiptSequence 投影为当前表示的连续前缀。普通 Projection 用它判断是否有新观察，可能丢失真实接收量大于已分析量的事实。Runtime 的新用户 steering/问答续接更新用户输入和约束，当前没有更新原 Cognition 情境块。

本次采取一个按用途读取的普通对话路径：读取当前关注、承诺、最近合法已选意图及其情境、直接关联和所需来源，复用领域现有读取器；不复用整页 PFC 待办，不新增分类模型、画像全注入、表、设置或持久缓存。最近已选意图继续遵守实际选择和依赖校验，不能改成任意最新已完成意图。

原始读取资源由宿主明确提供；它不等于 Token 配额，不由 Token 固定换算。未加载与不存在必须显式区分，范围和来源状态进入同一投影与完整输入计量。普通内容可在完整预算下选择，不能靠默默清空字段满足预算。当前既有16MiB原始行动读取选择只提供可复用的资源依据；新读取路径仍需实际验证，不直接套用旧查询时延。

新用户输入边界更新普通情境，重新构造和核算即将发送的完整请求。保存已执行的工具事实及选定行动依据；取消、输入竞争、重开与压缩沿原 Runtime 所有权。此次不增加固定模型步骤、后台排空等待、自动续调次数或独立模型窗口限制。

## 待验收

- 大量未读事件下，已提交的当前断言与限定条件仍可读，相关来源按需供给；未选的无关事件不会因窗口大而进入普通对话。
- 同一对象的不存在、字段未加载、摘录与已回收分别可见；真实接收边界不被投影前缀覆盖。
- 最新已选完成意图、实际行动回执及直接关联保持原资格；缺失或过期状态不被恢复成活动任务。
- 用户 steering、结构化答复、准备期间再次输入、取消和真实 SQLite 重开保持新输入与新情境一致；完整 wire 仍受258000及更低 Provider 限制。
- 正常工具续步不增加分类/分析调用；自然任务实际获得并采用内容的证据与纯机械回归分开记录。

## 当前集成与验证

`prepareTurn` 现经同步只读的 `readConversationContext` 读取当前语义、活动或暂挂承诺、最近合法已选意图及一跳直接关联；普通输入不携带旧 Episodes 全文。来源保持原资格，字段完整提供或明确未加载；coverage、真实接收量与原始SQL取值成本随读取一起返回。不会为普通回答强制排空后台事件。退出时仍排空实际已缓冲的Persona输入。

Runtime 在用户输入版本变化时删除旧普通情境和旧usage估计，保留选定行动依据、真实工具输出，再准备新情境。准备期间再次输入会使旧结果失效并重新读取；Stop/退出等待实际任务结束，不提交迟到结果。压缩保留行动依据及最新普通情境；恢复已有用户会话会重新读取已提交状态，不新增持久版本字段。
