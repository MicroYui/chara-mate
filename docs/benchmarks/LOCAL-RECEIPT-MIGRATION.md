## 问题与选定行为

25→26 升级需要重建观察来源表，加入 `unknown` 操作者。原实现复制仍存在的行、删除旧表再改名，却没有保留 AUTOINCREMENT 曾经分配的最高序号。若最高序号 40 已被正常清理，剩余行的最高值只有 9，升级会把序号回退到 9；若已全部清理，则回到 0。Cognition 已处理到 40 的游标保持原值，后续较小序号因此可能被当成已读。

修复在既有升级事务内读取真实 `sqlite_sequence`，完成原表重建后恢复旧值与新值中的较大者。读取使用 bigint，避免把 SQLite 整数先转换成 JavaScript 浮点数。没有新增升级版本、表、常驻状态或兼容运行路径，也不凭剩余行猜测已经删除的历史高水位。

## 一手依据

2026-09-17 核对 SQLite 的 [AUTOINCREMENT 语义](https://www.sqlite.org/autoinc.html)、[sqlite_sequence 文件格式说明](https://www.sqlite.org/fileformat2.html#the_sqlite_sequence_table)和[表重建流程](https://www.sqlite.org/lang_altertable.html)。历史分配高水位来自 SQLite 的持久状态；应用需要保持接收游标连续，是 CharaMate 的正确性要求。这里没有选取新的时间、容量或排序阈值。

当前受测路径为 Node 24.18.0、better-sqlite3 13.0.1 的实际 Apple Silicon 原生模块，`sqlite_version()` 返回 3.53.3；Node 自身报告的内置 SQLite 3.53.1 没有用于这些测试。
