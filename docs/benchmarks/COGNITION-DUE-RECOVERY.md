## 问题、来源与合同

Life3 的真实连续运行在来源用途错误后丢失了原先安排的 nextWakeAt，随后跨月推进没有重新考虑。2026-09-16 审查 common-v14（冻结 `79367e23f0f45fb0551e5580be0b8727c4ff6921594711c0fd12048ad1085dcf`）发现：Service 在 beforeAnalysis 与 Attempt 创建之前清除 Attention 到期时间，Repository 同时清除该角色全部到期 Intent。请求、读取或提交失败无法恢复；未供给模型的事项也被消费。这是旧源码行为，不是 Provider 协议限制。

产品 §1.6 中 nextWakeAt 表示届时重新考虑。发起请求不能证明考虑完成；明确提交的安静决定可以确认，失败不可以。已有 Run、用户暂停、并发修改及新安排沿既有状态恢复，不建立另一套生活计划或付费重试定时器。

## 单一实现

- Attempt 的可选宿主字段 wakeSources 只记录实际快照供给的到期 Attention 时间，以及 Intent 的 ID、revision、nextWakeAt。模型不能编写它；原 Attention/Intent 仍是唯一计划事实源。
- 读取与 Recall 准备阶段不消费到期事项。最终决策在同一事务提交状态，只确认本次实际供给且原版本/时间仍匹配的事项，再形成有效 read-set。未供给事项、并发修改、用户暂停及新未来安排保留；事务失败整体回滚。
- 重开恢复未绑定 Run 的失败/ready Attempt 时检查原依赖和用户 generation。已绑定 Run 继续原 reconcile，不重复派发。开始分析之前失败时，计划尚未消费。
- 同一生命周期抑制相同失败上下文的立即重复请求。真实意义输入、控制、计划/配置变化、服务重开或另一个既已安排事项到期允许重新考虑。纯计数、idle、记忆回流、重复或未变化的画面不触发付费忙循环。没有新事件时不承诺周期自动重试。

没有新增 DDL、表、进程、任务、Settings 或算法开关。Reader 在当前情境/承诺之后优先读取最早到期事项，仍遵守实际供给范围；无法容纳的事项保留原到期状态。

Root 后续审阅补了两处时间边界。v2 避免 08:00 的失败挡住失败前已安排的 09:00/10:00 事项；这些是原计划事件，不是新增失败重试时间。v3 以实际读取快照的时间捕获 due 与失败考虑范围：08:59 开始、09:01 才形成快照时，09:00 的事项已被看到，不能再次当作新到期，也不能在成功后漏确认。Attempt 原创建时间保持不变。
