# ACTIVITY-CAPTURE-RHYTHM：变化采集与截图触发

## 问题与边界

本 Decision 只冻结 Activity 的前台应用探测节奏、Idle 判定和截图触发方式。目标是保留可理解的状态变化，同时避免高频轮询、每秒事件和周期截图造成无意义写入、CPU 与磁盘增长。它不是监控、安全审计或隐私模式设计；产品仍只有“暂停/恢复”一个直接控制。

协议事件与产品启发式分开：Electron `43.2.0` 的 `powerMonitor` 提供 lock/suspend/resume 与系统 idle 状态，Playwright `1.62.0` 提供受管 Page 导航事件；它们不规定 CharaMate 的轮询秒数。以下数值都是产品启发式，只作综合决策证据，不以单项门槛机械否决整体更优方案。

## 来源、环境与冻结数据

- 执行日：2026-08-08；基线 commit `d539dff367a5e8af544d6dcf28e1112e8311d63b`；Apple M4 Pro、24 GiB、macOS/Darwin `25.6.0`、Node `24.18.0`、Electron `43.2.0`、Playwright `1.62.0`。
- 主来源：Electron `powerMonitor` / `desktopCapturer` 当前 API 与 Playwright `BrowserContext` / `Page` 事件；版本同锁文件。前台 macOS 应用通过系统 `System Events` 只读取 frontmost app、bundle id 与前窗标题。
- 冻结变化集由 `ACTIVITY-DISTILLATION` 的 30 日 transition 数据派生，并补入事先标注的 `6/10/20/45/120/600` 秒短停留；每个 interval 遍历全部相位偏移，避免只挑对某一 cadence 有利的采样起点。Idle 集预先标注 `<45` 秒为短暂停顿、`>=60` 秒为真正离开。
- runner 另在目标机重复读取当前应用，记录真实单次 probe 延迟；它不切换用户前台应用，也不截取或保存屏幕内容。

冻结集、runner、原始结果与 hash 在结果产生前只保存于仓库外持久证据目录；最终删除候选 runner，仓库只保留本记录。

## Arms 与唯一变量

### 前台应用

| Arm | 采样间隔 | 其余行为 |
| --- | ---: | --- |
| `P5` | 5 秒 | 只在 app/window/actor 变化时落一条 transition |
| `P15` | 15 秒 | 同上 |
| `P30` | 30 秒 | 同上 |

### Idle

只比较 `30/60/120` 秒三个判定值；lock/suspend 始终立即切断，不受该数字影响。

### 截图

比较 `S0-PERIODIC15M`（活跃期间每 15 分钟）、`S1-TRANSITION`（每次检出的变化）与 `S2-TRANSITION15M`（只在变化时触发，且距上次至少 15 分钟）的日文件数、Episode 覆盖和实现状态。15 分钟由 `ACTIVITY-RETENTION` 的 7 日截图层、512 MiB 原始层上限与冻结资产大小反推为保守探针，不成为设置。截图内容不参与本实验打分，避免为 cadence 选择引入视觉模型变量。

## 指标与综合选择

- transition event 检出率、时长加权覆盖、检测延迟 p50/p95、短事件漏检；
- probe p50/p95、估算每日调用数与进程占用；
- Idle 误报、真正 Idle 切分延迟；
- 截图数/日、Episode 覆盖、资产增长；
- 状态、恢复、错误处理和维护复杂度。

应用变化、Idle、锁屏、actor 变化必须能切断 Episode；其余数值没有机械晋级线。若 `P5` 的短事件增益主要来自低信息数秒切换而成本约为 `P15` 的三倍，允许综合选择 `P15`；若 `P30` 仍明显漏掉有意义停留，则更低调用数不构成单独胜出理由。

## 结果

首轮 runner 把各 interval 的全部采样相位检出数直接写成截图数，分母错误；该输出在任何产品定案前标为 invalid 并原样保留。修正版只改变截图聚合与派生资源字段，不改变冻结事件、采样 Arms、Idle Arms 或 probe 请求。修正版原始结果 `activity-capture-raw.json` 的 SHA-256 为 `fb8074782dc9a887f5cf712000c3b38894a1ce3dbd3dcaf52d2bbe1aed7017db`。

240 个变化事件遍历每个采样周期的全部秒级相位；因此三个 Arm 的分母分别为 `1,200 / 3,600 / 7,200` 个 event-phase observation。有意义事件以预注册的 20 秒及以上停留为准。

| Arm | 全变化检出 | 有意义变化检出 | 时长加权覆盖 | 延迟 p50 / p95 | 估算调用/日 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `P5` | 1,200/1,200（100%） | 960/960（100%） | 100% | 2 / 4 秒 | 17,280 |
| `P15` | 3,264/3,600（90.7%） | 2,880/2,880（100%） | 99.65% | 6 / 14 秒 | 5,760 |
| `P30` | 5,904/7,200（82.0%） | 5,520/5,760（95.8%） | 99.09% | 13 / 28 秒 | 2,880 |

目标机 40 次只读前台应用 probe 的 p50/p95 为 `158.6/177.7 ms`。按 p50 外推，P5/P15/P30 的子进程 wall time 分别约为 `2,740/913/457 秒/日`；这是调用成本代理，不等同于持续占用一个 CPU 核。P5 相对 P15 只补回少数不足 20 秒的低信息切换，却增加三倍调用；P30 虽再减半调用，但漏掉 240/5,760 个有意义 observation，且 p95 发现延迟增至 28 秒。

Idle 30 秒检出 4/4 次真正离开但产生 2 次短暂停顿误报；60 秒为 4/4、0 误报；120 秒仅检出 2/4。截图在 P15 上的日均探针如下：

| Arm | 截图/日 | Episode 等权覆盖 |
| --- | ---: | ---: |
| `S0-PERIODIC15M` | 54.0 | 22.5% |
| `S1-TRANSITION` | 217.6 | 90.7% |
| `S2-TRANSITION15M` | 48.0 | 20.0% |

截图覆盖不是 Activity 事件覆盖：每个 Episode 仍由 app/browser metadata 完整记录，截图只是少量视觉佐证。S1 每日文件约为 S2 的 4.5 倍，会快速挤占 K3 的 512 MiB 原始层；S0 与 S2 数量接近，但 S0 即使没有状态变化也定时保存。S2 以更低文件数把截图对齐到真实变化，代价是等权 Episode 截图覆盖比 S0 低 2.5 个百分点。

## 综合定案

选择 **`P15 + idle60 + S2-TRANSITION15M`**：每 15 秒只读一次前台状态且仅在变化时落 event；系统 lock/suspend 仍立即切断，连续 idle 60 秒切断；截图只在变化时触发且距上次成功触发至少 15 分钟。P15 保留全部预注册有意义变化，成本显著低于 P5；idle60 是唯一同时无误报且不漏已标注真正离开的 Arm；S2 让截图斜率与 K3 容量策略相容，并避免无变化周期截图。

这不是三个可配置档位。生产只保留上述常量和一个暂停开关；Agent Run actor 独立保存，蒸馏不得把 Agent 操作归为用户行为。截图失败只影响该份视觉佐证，不阻断 metadata event 或 Chat/Agent。

受管浏览器导航保存为 metadata point，不重复计算前台停留时长。若同 actor 的前台应用事件仍打开，蒸馏会等待该事件闭合并把导航折叠进同一 Episode；只有确实没有重叠前台事件时，导航才独立成段。这样既保留浏览器语义，也避免长时间停留期间较早的导航点被提前固化成重复 Episode。

截图始终只是 Episode 证据：通常并入覆盖其时间点的前台 Episode；只有 Browser point 而没有前台探针时，并入紧邻的 Browser Episode；两者都不存在时形成一个最小截图 Episode。最后一种情况不推断用户意图，只保证这条 raw event 能完成蒸馏并进入同一保留生命周期，而不会永久滞留在未处理队列。

## 限制

- 合成短停留用于公平比较 cadence，不等价于长期真人遥测；本实验只能支持低频桌面变化采集的首版数字。
- 单屏目标机的系统 probe 延迟不能外推到所有 macOS 版本；生产错误需可恢复且不能阻断 Chat/Agent。
- 本实验不评价截图语义质量；图片直载与视觉支持属于 `P3-MULTIMODAL-INPUT`，Activity 这里只选择何时采集。
