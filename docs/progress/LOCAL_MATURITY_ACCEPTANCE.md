## 1. 验收证据与模拟边界

用户明确允许用 mock 连续事件、可控时钟和跨日/跨月数据替代等待真人长期使用。本轮以这种可重复纵向验证满足本地功能验收，不再把必须等待数月真人数据作为工作阻塞条件。模拟只替代环境、时间和用户经历；被验收的形成、检索、认知决策、持久化、恢复、上下文与普通 Agent 消费仍调用实际产品实现。模型语义质量使用真实 gpt-6-astra；本地编码与向量执行使用实际选中资源。独立脚本根据标签直接生成正确状态，或把正确答案放入消费者输入，不能作为产品验收。

验收同时报告具体用户结果、内容与条件保留、检索覆盖和采用、错误恢复、人为管理负担、模型/Tool 调用、输入输出 Token、墙钟延迟、主线程响应、内存和存储增长。多日模拟能验证机制和连续语义，不被表述成真人数月情感收益。正常陪伴界面不增加算法参数或研发控制。

确定性正确性包括：不把请求/许可/自述伪装完成，不覆盖用户改口，不将推断升级成事实，不把一次会话重复和模型曝光当多日支持，停止和恢复不重复执行已完成副作用；这些是实际功能约束。相关自然语言解释也要真实模型验证，不能只检查 Schema。

实验中的样本量、扰动强度、时间跨度和候选预算是可解释的工程研究条件，不是脑科学常数或模型协议限制。晋级综合质量、区间、效果、资源和复杂度；有结果后改变取舍需保留原结果并说明，不悄悄调低门槛。失败保留，开发重测与最终独立场景分开，不以反复重试直到成功替代失败率。

## 3. 必须被建模和实际观察到的行为

### 3.1 事件、情境与注意

相同应用多事项、同一事项跨应用、前后台变化、相同标题的不同窗口、返回旧页面、新内容/迟到旧内容、用户和角色同时操作、局部不可读、多模态缺口、睡眠与恢复都需要有真实来源与状态语义。单纯频率与时间不能成为兴趣或情绪结论。

决策不仅给事件分类，还要保留当前解释、相关用户/角色目标、什么发生变化、仍缺什么、为何现在行动/安静/等待以及实际反馈。竞争情境中验证重要纠正与未完承诺不丢、无关干扰不重复开场、切换可恢复，分析/检索在途的旧结果不能覆盖新用户意图。

画面验收分别证明原生捕获并保存、实际模型请求收到该像素、形成可用解释以及最终回答正确。本次新鲜窗口必须有一条贯通证据链；既有PNG语义测试与本次采集成功不能拼成理解证明。普通Chat应能按问题定位尚未形成Claim/Episode的保留画面，并读取精确版本；当前画面与旧观察、只有OCR与实际像素、尚未返回与已清理明确区分。用户自然提问不预填答案、路径或命中引用。

### 3.2 用户意义、情感与角色日常

用户直接表达的感受、经历的意义、应对能力/限制与支持偏好保持不同依据；多个合理解释可以并存并被纠正。角色不能从打字快、沉默或悲伤文章断言用户焦虑。该模型必须在真实回答和动作中体现具体差别，不能以加入字段或通用安慰提示词验收。

角色持久兴趣、价值、阶段目标、已完成经历和可执行能力应形成连贯活动。跨日模拟验证未完成的继续、计划改变、失败后的调整、休息、用户接管与恢复；禁止虚构离线经历。小活动自主，用户无需维护内部目标表。丰富性按连贯结果与重复负担评估，不以随机动作种类数代替。

### 3.3 形成、检索与使用

对复杂原话和混合来源逐项检查主体、事实、情绪/因果背景、否定、限定、发生/有效时间、纠正、约定与执行状态。第一步抽取和旧记忆比较后的结果分别保留，以定位“没提取”“比较时丢失”“未召回”“选择挤出”“最终漏用”；不能只看最终一条摘要似乎合理。

历史修订必须区分“曾经成立、后来改变”和“原先记错、后来纠正”。前者可以作为真实过去的经历、偏好或计划；后者可以回答“当时说过什么”，但要带纠正标注，不能再作为真实历史、完成证明、巩固或领地生成的依据。要验证多次修订与更早版本被纠正、原文回收后的标注保留，以及生成在途时依据变化；仅让 history 引用通过版本校验不算满足这项要求。

最终冷检索输入通过新 Chat、进程重启和经过正常情境收束形成，不向普通 Agent 提供旧答案、命中 ID 或评测类别。真实 memory.search 的问题、候选、选择、Pack 和最终使用分别记录。包括精确旧事、跨会话组合、时间更新、同名不同人、隐含约束迁移、必要限定、已取消承诺、没有答案与普通问候。引用正确但回答错、检索不曾执行、首步已有答案，分别计量而不混为成功。

### 3.4 巩固与遗忘

记忆内容、检索可达性与当下使用分开。用户活动时钟不由后台唤醒、检索或脚本重复累加；同会话多次提及与跨日独立支持不同。未来需求预测须能与无预测基线比较，并解释冷启动、低频重要约定、长期停用及突发重提行为。

2026-09-17 选型收口：以上时钟与预测是需要比较的机制，不能仅因最初列入候选便要求常驻生产。依据 Product §6.4、[曝光中性与旧事可达性](../benchmarks/COMPANION-MEMORY-LIFECYCLE.md)和[巩固选型](../benchmarks/MEMORY-ADAPTIVE-CONSOLIDATION.md)，当前选择不按机械年龄降低有效事实可达性、不将检索曝光视为强化，并保留单一 FIFO 巩固准备。真实来源去重后的日期桶不是活动时钟；不声称已实现预测排序或自动年龄遗忘。目录对照的完整性优势、FIFO 原漏答及事后复杂度取舍均保留，查询修复后的独立质量仍须验收。上述低频旧事、停用、重提、纠正传播及可恢复的产品结果要求不变。

巩固输出必须保留原证据、适用场景和推断性质。纠正、删除、否认或来源失效后，派生理解不能继续冒充有效事实。减少常态工作集不得让明确旧事查询不可达；新记忆保护和可逆回收要通过真实读取和恢复验收。过程需要有界读取、幂等提交和可恢复失败，不能靠周期全库重写解决容量。

局部材料额度遵循用户最新约束：8,192 与 32k 都只是开发比较条件，不能成为不可突破的产品上限。行动所需的当前目标、关键条件、反证和实际依据必须完整；普通接话的补充情境与自主行动的必要材料分别建模。最终空间由任务需求、真实组装后的完整请求和 Provider 更低限制共同决定；通过相关性选择减少干扰，不因固定小额度而反复观察或重做决定。评价包含最终成功率、重复读取、重新决策、总调用与延迟；不能仅以单次 Token 减少作为晋级证据。

### 3.5 资源和本地交付

语义纵向轨迹与高频容量负载分开运行，再做合并负载。实际记录 Main 事件循环、原生 AX/SCK 延迟、编码器与向量 Worker、SQLite/WAL/原文/引用/资产增长、取消/退出后的句柄和内存；提前给定热身和测量段，避免挑单次最好结果。容量目标来自本机和产品形态测量，不将合成十万向量称十万真实用户。

完整请求必须覆盖指令、工具、结构、历史、图片/文件等。258,000 是用户硬上限，与更小 Provider 限制取交集；近界请求不能用无依据字符估算称精确通过。代理能力不足时要落实可用的受支持计数或明确的边界行为，不能以测试 mock count 成功证明代理提供真实计数。

图片读取和观察定位属于同一Run生命周期：Stop/退出需等待实际读取任务收口，取消后不写迟到成功；同步原生解码只检查调用前后，不能称可中途抢占。重启从来源引用重新校验像素，已完成的读图结果不重复执行Tool；新用户输入、当前任务已实际读取的不同图片以及最后其它Tool回执在压缩后均保持可见；同源重读只保留最近一份，必要工作集超限不静默丢图。

## 4. 分阶段评测协议

1. **开发诊断**：上一轮缺陷与新领域的明确场景，保留基线和每次实际输出。候选只改变指定机制，来源、模型、输入及预算保持可比较。
2. **跨日/跨月连续运行**：模拟活动、消息、Tool 后果与时钟，真实运行数据库、形成、索引、PFC、Agent。包含稳定习惯、改口、长期缺席、多个并发事项、兴趣转移、角色失败与恢复。冻结故事与检查点后才比较候选。
3. **独立组合验收**：新故事家族与未用于修改的措辞/组合；单独封存预期事实和行为标签，产品运行器只读事件与用户问题。对开放表达盲化候选身份，结合约束检查和人工语义复核，不能只用关键词或同一生成模型自称正确。
4. **实际平台与容量**：使用自有应用窗口、独立 userdata、真实本地模型和生产进程测试。可控时钟模拟年龄，真实墙钟测资源。没有外部执行回执的模拟不能证明真实文件/日历/社交动作发生。
5. **唯一生产集成**：赢得比较的机制简化并纳入单一实现，删除候选代码/依赖/开关；最终同版跑 required regression、实际包及受影响连续场景的定向复测。原48保持原冻结版本和分母，不为最终封板自动重跑。旧结果和失效假设保留在 Decision，当前 STATUS 只报告当前版本。

每个专题在调用模型前补齐各自的版本、数据标识、样本覆盖、比较方式、指标及晋级条件。初始方法参考 [LongMemEval](https://github.com/xiaowu0162/LongMemEval) 的跨会话/更新/时间/拒答维度、[LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2) 的轨迹记忆→紧凑证据→下游回答，以及 [LoCoMo-Plus](https://arxiv.org/abs/2602.10715) 的无显式旧事提示下约束一致性；查阅日 2026-09-16。它们不提供 CharaMate 默认参数，也不代表本产品已达到外部榜单水平。
